## Ограничения и ручная проверка перед релизом

1. Самостоятельного получения заявки без WhatsApp нет и не требуется текущим ТЗ. Для CRM/email/DB нужен защищённый backend/form service и отдельная реализация адаптера.
2. Настоящее нажатие Send в WhatsApp, Telegram-бот и реальные iOS/Android устройства — NOT RUN. Автоматизация проверила handoff URL/структуру и браузерную адаптивность. Ссылка Telegram ответила HTTP 200.
3. Safari/WebKit и Firefox — NOT RUN; проверен установленный Chrome / Chromium. Казахский текст готов, но редакторский review носителем языка полезен перед публикацией.
4. Public interfaces могут изменяться. У двух продуктов нет предоставленных screenshots, используются честные обложки. Новые метрики/сотрудники/отзывы/цены не выдумывались.
5. GitHub project Pages выдаёт один общий 404.html на русском с восстановлением на три языка. Локальные KK/EN 404 существуют, preview выбирает их по адресу. Это ограничение статического хостинга.
6. Robots в поддиректории не управляет корнем origin GitHub. Sitemap/canonical/hreflang подготовлены корректно; после публикации проверить индексацию и опубликованные assets.
7. Root legacy index.html сохранён без изменения. Новую версию публикуют из dist через подготовленный ручной workflow, после одобрения merge и изменения source Pages.
